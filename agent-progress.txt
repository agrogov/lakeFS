### What is wired, and what is only written

Three gaps are code that exists and tests that pass, but no production caller. They are the reason
`docs/iceberg.md` has a "Current limitations" section and §15.4 of the plan has a status table:

1. `pkg/icebergcatalog/files.go` stages a snapshot's files as lakeFS entries, but `commit.go` never
   calls `StageTableFiles`. So table files are not in the GC's view, a diff shows only the pointer,
   and a merge carries only the pointer. §6.3's guarantee is therefore **not** in force yet.
2. `UncommittedGCProtected` (`gc.go`) and `ReservedPrefixProtectPolicy` are implemented and tested,
   but nothing in `pkg/catalog` or the auth bootstrap calls them: the grace window does not filter the
   prepare step, and the `_lakefs_iceberg/` deny is not attached at bootstrap.
3. `NewRemoteSigningService` and `NewCredentialService` have `Routes()` and handlers, but
   `RoutesBuilder` appends only the namespace and table services, so neither endpoint is mounted or
   advertised. `LoadTableResult.config` is empty and clients fall back to their own credentials.

A fourth is a one-line wiring choice rather than missing code: `http.go`'s `newAuthMiddleware` still
builds `api.GenericAuthMiddleware` instead of the catalog's `NewAuthMiddleware`, so
`POST /v1/oauth/tokens` is not served. Basic auth and bearer JWTs work; the client-credentials
exchange that PyIceberg/DuckDB use for `credential=` does not.
